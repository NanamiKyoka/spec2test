# 演示视频脚本（录屏版，3:20–3:30）

目标：让没看过项目的评委在 3 分半内记住「规范 → 测试意图 → 确定性校验 → 证据 → 可带走」。全程只展示产品，不做 PPT。官方要求 3–5 分钟，**不要压到 3:00**。

## 录制前检查
- 浏览器 1920×1080，缩放 100–110%；隐藏书签栏；关闭通知。
- 服务已启动：`start.bat`（同时拉起 `:3000` 界面与 `:8000` API）；右上角状态为绿色。录完关闭 `start.bat` 窗口，避免个人路径入镜。
- **下载目录**设为专用空文件夹（如 `E:\demo\exports`），不要用默认 Downloads。
- **不要出现**：API Key、`data/settings.json`、终端里的密钥、个人路径。
- 预跑一次 `bash scripts/verify_clean.sh` 并保存输出；**成片只回放输出，不现场跑**（不同机器可能没有前端依赖，UI 冒烟会被跳过）。
- 模型不可用时走「快照路径」：评测页、单例页、导出仍可录；跳过对话页实时运行。
- 先把一次语义匹配跑到 HITL 审批卡（600 秒超时内），再开始录对话段，避免现场等模型。

## 时间轴与台词

### 0:00–0:12 开场（画面：`/eval`）
**台词**：
> 3GPP 测试用例现在靠人从规范里抄条款、拼步骤、填字段。大模型能写，但写错了没法判错。Spec2Test 把条款编译成测试意图，再用确定性校验器判对错。

**动作**：画面停在评测总览标题与四张统计卡。

### 0:12–0:40 先看硬指标（画面：`/eval`）
**台词**：
> 8 个用例、22 次 IE 生成调用；31 条注入缺陷全部检出；8 份官方答案零误报。下面是判定分布和按规则的缺陷检出。

**动作**：鼠标缓慢划过四张卡与两张图；点开「缺陷检出」卡的 `?` 2 秒，露出“自建模板、修正 4 条无效注入”的口径。

### 0:40–0:55 矩阵怎么读（画面：`/data`）
**台词**：
> 数据页的逐例矩阵：绿通过、灰弃权、红拒收；点用例号看字段级证据。这里不报平均数，因为只有 8 例。

**动作**：指矩阵图例与 6.7.1.3 行，点击用例号。

### 0:55–1:45 单例页：结论 → 解读 → 证据（画面：`/case/6.7.1.3`）
**台词**：
> 6.7.1.3 测的是：网络把当前卫星小区标记为禁止接入后，终端会不会离开并重选。先给结论：通过；再用五段话解释这条用例在验什么、系统生成了什么、为什么是这个判定、数据怎么读、哪里还不确定。

**动作**：慢速滚过「结果解读」五段；向下滚到「明细」；点 `cellBarredNTN-r17` 字段，打开证据抽屉，停留 3 秒。

**台词（抽屉）**：
> 每个字段都能指回符号表路径；通过时没有违规，违规时会给出 R1/R2/R3 的路径。

### 1:45–2:45 对话工作台：直接跑与人在环上（画面：`/`）
**台词**：
> 也可以直接在对话里说。精确用例号直接跑；语义匹配时，意图识别会先调用一次轻量模型，但生成调用必须等人批准。

**动作**：
1. 在对话框输入「跑一下 6.7.1.3」，回车；出现**运行卡**，按阶段滚动（ingest → context → candidates → generate → validate → score）。
2. 等运行卡变为完成，指卡片上的判定与一句白话结论。
3. 再发一条场景请求（如「卫星小区被禁止」）；出现「待确认：候选消息」**审批卡**，鼠标停在候选消息与两个按钮上 2 秒。
4. 点「取消」（不批准），观察任务进入「已取消」，**不发起生成调用**；随后结果卡显示取消原因。

### 2:45–3:05 结果卡与证据页（画面：`/` → `/case/6.7.1.3`）
**台词**：
> 每条结果都带判定、校验结果和证据入口；点进去就是字段级证据，能一路指回符号表。

**动作**：点结果卡的「查看证据」，跳到 `/case/6.7.1.3`；指顶部结论与证据抽屉入口；再返回对话工作台。

### 3:05–3:20 弃权、局限与可复现（画面：`/case/6.7.1.4` → `/eval` → 预录终端）
**台词**：
> 6.7.1.4 的输入里没有消息名。页面仍有 26 步，但只保留消息名，没有 IE 字段取值；阶段二未调用模型，也不计 0 分。弃权不是失败，是拒绝编造。评测页也把局限摊开：L3 分母 7 例、L2 不计分、6G 未标准化。

**动作**：指步骤表顶部的弃权说明；切到 `/eval` 指「已知限制」中的弃权口径与 relaxed 基线；再切到预录的 `verify_clean.sh` 输出（clone → serve → 健康检查 → clean-clone PASS）。

### 3:20 收尾（画面：`/about` 或 `/eval`）
**台词**：
> 我们的主张只有一句：规范就是标准答案；校验器说不行，就不写入结果；信息不足，就弃权。谢谢。

## 失败/风险预案
- **模型超时或报错**：不要现场重试；切到预置完成结果或快照，按 0:00–1:45 继续录。
- **导出被浏览器拦截**：提前允许下载；或直接打开 `E:\demo\exports` 展示文件。
- **端口被占用**：`start.bat` 会提示已在运行，直接打开 `http://127.0.0.1:3000/`；不要在视频里杀进程。
- **录到密钥/个人路径**：重录该段；不要用模糊遮盖，直接不录设置页明文。
- **verify_clean 没有 UI 冒烟**：评委机可能没有前端依赖，口播说“页面与快照检查通过”，不要念具体条数。

## 成片检查
- 3:20–3:30；≤300MB；MP4；有声音；无密钥、无个人路径、无通知弹窗。
- 开头 15 秒内出现「条款 → 测试意图 → 校验器」。
- 三个硬指标（8、22、31/31、0/8）与「弃权不编造」至少各出现一次。
- 结尾 10 秒内出现可复现命令。
- 所有数字念法与页面一致：`31 / 31`、`0 / 8`。
