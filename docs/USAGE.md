# 使用指引（USAGE）

## 一、先说清楚它是什么

**它不是聊天机器人，是一个"编译器 + 校验器"。** 输入是 3GPP 规范条款，输出是结构化测试意图，并附一份"哪里错了"的机器判定。

用编译器类比最准：

| 编译器 | Spec2Test |
|---|---|
| 源码 `.c` | 规范条款 / 测试目的 |
| 编译产物 `.o` | IR（步骤 + 信令 IE） |
| 类型检查器报错 | 校验器 R1/R2/R3 违规 |
| 单元测试跑分 | 逐例 L1 / L3 评分 |

对话只是**外壳**。真正决定价值的是"产物可被机器检查"，而不是"能聊"。这也是我们和"把条款贴给 GPT"的分界线——后者能聊，但没有编译器，也没有类型检查器。

## 二、三种用法

### 用法 A：批量评测（做实验、出分数）

```bash
bash scripts/repro.sh          # dry-run，产物在 data/_repro/，桩数据，不可用于报告
bash scripts/repro.sh --live   # 真实调用模型，写 data/，产出可用于报告的分数
```

产物：`data/out/`（每例 IR）、`data/score/report.json`（逐例 L1/L3）、`data/score/abstain.json`（弃权统计）。

**谁用**：想验证"这套方法到底行不行"的人。评委验证你，你验证自己。

### 用法 B：看单个用例的全链条（理解系统怎么工作的）

```bash
start.bat                        # 同时起 Python :8000 与 Next :3000
# 或分两步：py -3.12 scripts/serve.py  +  cd webapp && npm run dev
# 浏览器打开 http://127.0.0.1:3000/
```

点任一用例 → 进入 `/case/6.7.1.3`，能看到六个阶段：
`ingest（读规范）→ context（裁剪条款）→ candidates（抽候选消息）→ generate（生成 IR）→ validate（校验）→ score（打分）`

**关键看两件事**：
1. 候选消息为空时，后三个阶段显示 `skipped（弃权）`——**这是正确行为，不是失败**；
2. validate 阶段会指出具体违规位置（哪条规则、哪个字段、哪一步）。

**谁用**：想搞懂"智能体每一步在干什么"的人。

### 用法 C：对话式（已实现）

输入用例号或描述场景；精确命中直接跑确定性阶段，语义命中先展示候选消息并等待人工批准，再调用模型。结论、六阶段与违规都在对话流里展开。

**谁用**：想按"问一句 → 看结果"方式使用的人；也是 HITL 审批的入口。

### 用法 D：把结果带走（导出测试意图）

1. 打开单例页（如 `/case/6.7.1.3`）；
2. 点「导出 Markdown」用于评审/归档，或「导出 JSON」接入用例库/CI；
3. JSON 保留 `steps` / `messages` / `violations` 与 `provenance`，Markdown 直接可读。

弃权用例仍可导出，文件会明确写"未生成信令内容、步骤为结构解析产物"。

**谁用**：测试工程师、认证实验室、工具链团队。

## 三、对话式入口（当前实现）

当前交互如下（语义命中时会在生成前插入 HITL 审批）：

```
你：6.7.1.3 这个用例，帮我补一条"UE 未收到 RAR 时重发前导"的步骤

系统（流式）：
  ✓ 定位用例：6.7.1.3 / NR NTN / 服务小区不可用
  ✓ 裁剪条款：TS 38.331 §5.3.3（3 条）、TS 38.321 §5.1（2 条）
  ✓ 候选消息：SIB1
  ⏸ 等待人工确认候选消息（HITL）→ 批准
  → 生成步骤 4 条 …
  → 校验：R3 未通过 —— 你的新步骤没有覆盖 TP(2) 的 then 条件（路径 steps[4].tp_ref）
  ✗ 已拒收，未写入结果
```

**与普通聊天机器人的三条区别**（也是它能自证的原因）：
1. 每个结论都能指回条款编号；
2. 不合格的产物会被**拒收**，而不是照样回给你；
3. 同样输入重跑，结果与分数可复现。

**当前状态**：后端已具备全部能力（生成、校验、评分），缺的只是这层对话外壳与流式回传。预计 0.5–1 天。

## 四、常见问题

**Q：为什么要"弃权"？直接生成不行吗？**
本切片里有 2 个用例的输入文本根本不含消息名，任何方法都推不出官方信令内容。此时强行生成就是编造。系统选择明确说"信息不足"，而不是给你一段看起来像样的假内容。这也是我们和裸模型的差别之一。

**Q：分数为什么不高？**
L3 召回受输入信息量限制（见 `docs/EVAL.md`）。我们不报平均数，只报逐例矩阵，并同时列出基线在同一批用例上的表现。

**Q：能处理 6G 吗？**
不能，因为 6G 规范化 2028-12 才冻结，目前不存在可测规范。本系统在 NR Rel-19 上验证，方法对规范代际变化同构（见 `docs/adr/0001`）。

**Q：我只有 Claude/OpenAI 的 key，能跑吗？**
能。模型调用统一收敛在 `tools/llm.py`，支持代理 / OpenAI 兼容 / Anthropic 官方三种通道，用 `LLM_PROVIDER` 切换（见 `docs/P1-REPORT.md`）。

## 五、一分钟上手

```bash
# 1) 看结果（不需要任何 key）
start.bat                      # 双击，或 python scripts/serve.py
# 2) 看某例全链条
#    浏览器 → 点一行用例
# 3) 自己重跑（需要模型通道）
bash scripts/repro.sh --live
```
