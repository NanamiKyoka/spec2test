# 项目基线（2026-10-29 定稿·初赛）

## 作品名称
**Spec2Test：自证式测试意图编译器**（20 字）

## 一句话定位
面向 3GPP 系测试规范的「条款 → 可执行测试意图」编译器，生成后自带确定性校验与判错。6G-ready，在 NR Rel-17/18/19 上验证。

**主张（2026-10-29 定）：可验证性优先于召回，信息不足则弃权（ADR-0006）。**

## 切片
- 主展台：TS 38.523-1 §6.7 NR NTN 空闲态小区选择/重选，**8 个用例**做穿。
- 另 8 个散落 NTN 用例只列入"覆盖计划"，不实做。
- 对照：地面网（TN）用例 3 例，仅作定性对照。

## 链路
条款原文 → 检索（38.300/38.331/38.321/38.508-1）→ 结构化 IR → 生成 TP/步骤/信令 → **确定性校验器** → 判分。
校验器知识源：V1 手建符号表 + V2 从 38.331 半自动抽字段路径后人工筛。**禁止用 LLM 充当校验器。**

## 评测
- L1 结构合法 / L2 步骤对齐 / L3 关键 IE 命中，全部程序判定；**不做 L4**。
- **不报平均数**，报逐例矩阵 + 定性分析（8 例无统计意义）。
- 必须含"裸 prompt 基线"对照。
- 校验器独立指标：**缺陷检出率**（注入 20–30 条错误用例）。

## 交付
**当前阶段（2026-10-29 起）以"可运行的产品"为唯一目标。** 方案 PDF、演示视频、答辩 PPT、队友招募**全部冻结**，不再投入工时（用户指示：先把产品拿出来）。

**2026-10-31 更新**：用户选择「冲奖」，解冻方案 PDF/演示视频/答辩 PPT；产品仍以可运行优先，不因排版牺牲功能。
产品定义：仓库可克隆后按 README 跑通「规范 → 基准 → 生成 → 校验 → 评分」并产出逐例结果；失败案例可复现。
不做：容器化、在线 demo、UI 美化。

## 时间
10/29 起 16 天，11/13 收口。有效工时 50–60h（有课，兼职）。

## 明确不做
多模型切换、可视化编辑器、多语言输出、插件系统、登录、数据库、云部署、跨域迁移实验。

## 团队
- 先落实队友 A（工程：前端 demo、复现脚本、环境），**真实参与，不挂名**。
- 队友 B（排版/视频/PPT）暂缓；若时间允许再补。
- 独狼参评会在「团队协作 10 分」与「研发基础与团队能力」上结构性失分，故必须补 A。

## 知识产权
- **不申请软著**（2026-10-29 决定）。理由：加急需 1–1.5 天产出源码+用户手册，与 P2 校验器冲突；不为此牺牲命门。
- 方案中如实说明"暂无知识产权，以可复现性佐证"，佐证材料用可复现性证据包替代。

## 不可谈判
1. 明说 6G 未标准化（ADR-0001）。
2. 遮住官方答案做评测，脚本开源（ADR-0002）。
3. 校验器必须是确定性的，不是 LLM。
