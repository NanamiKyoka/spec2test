# 产品主张：可验证性优先，信息不足则弃权

实测发现 L3（信令 IE 召回）无法超过裸 prompt 基线，根因是**官方答案用到的消息名在输入文本中并不存在**（6.7.1.4、6.7.1.12 输入侧 `SIB` 命中为 0）。基线的高分来自模型先验——它凭记忆写出常见 SIB 结构，而这些输出无法追溯、无法被判错。

据此确定产品主张：不追求原始召回，而以「结构 100% 合法 + 每条 IE 可追溯 + 生成物可被判错 + 输入不足时明确弃权」为核心。**弃权是一等行为**：候选信息为空时输出 `status=abstained` 与原因，不输出 IE。

**Why:** 在一台评委面前，"我们的分数低是因为不说没依据的话"是能站住的；而"分数高但每条都无从追溯"恰好是这套方法要解决的原罪。放弃召回换可验证性，是与基线形成真实差异的唯一路径。
**How to apply:** 任何对外结论必须并列给出三件套（L1 合法率、校验器误报数、缺陷检出率）与弃权/幻觉计数；不得单报 L3，也不得用领域先验提分（已在 8 例上否决，属过拟合且破坏可自证性）。

## Consequences
- L3 低于基线是**预期结果**，不是缺陷；报告中必须解释其成因，并同时给出基线的"无依据生成"计数。
- 产品必须实现并暴露弃权路径，否则该主张无法验证。
