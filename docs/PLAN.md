## 三、目标架构

```
app/ (Vite+React+TS)  ──build──▶  web/ (静态产物, 自包含)
                                     │
scripts/serve.py  ──── 静态服务 + 12 个 /api 端点 ────▶ tools/ (生成/校验/评分)
                                     │
                              data/ (运行产物) ◀── results/ (交付快照, 入库)
```
依赖方向单向：前端只调 `/api`；`tools/` 不依赖前端；`validate` 只读 IR 与符号表，**不调模型**。

## 五、优化目标（按优先级）

### P0 可用性（不做就是半成品）
1. **首屏三步引导**：是什么 / 怎么看结果 / 点哪里开始；关闭状态记忆。
2. **术语就地解释**：L1、L3、gold、verdict、弃权、符号表。
3. **指标可追溯**：每个指标卡 `?` → 计算式 + 分母 + 已知限制。
4. **结果固定结构**：结论 → 一句话说明 → 六阶段 → 违规 → 原始 JSON。
5. **空态给动作**：不出现"暂无数据"。
6. **弃权语义**：灰点、非红；文案明确"未调用模型、不计分"。

### P1 体验（决定"像不像产品"）
7. 会话：新建/切换/双击改名/删除确认/当前高亮。
8. 对话：IME 正确、严格贴底、上滚不被拽、复制、重试、停止语义诚实。
9. 生成中：`readOnly` 光标隐藏、进度「已等待 N 秒 · 当前阶段」、轮询退避 1s→3s。
10. API 页：切换通道不覆盖手改值；模型列表 catalog/error 两态说明；密钥掩码。

### P2 打磨（时间允许）
11. 暗色主题一致性、动效克制（只保留 150ms 内的过渡）。
12. 移动端抽屉与安全区。
13. 键盘可访问性（Tab 顺序、Esc 关闭、焦点环）。

## 六、质量红线（任何一条不满足即不得交付）
1. 页面不出现裸的 `undefined` / `NaN` / `[object Object]`。
2. 明文 API Key 不出现在 DOM、console、URL、会话记录。
3. 弃权不得显示为失败或 0 分。
4. 拒收（reject）不得写入 `data/out/`（只能进 `data/out_rejected/`）。
5. 分数与口径三处一致（`report.json` / `abstain.json` / `docs/EVAL.md`）。
6. 断网可用：`dist/` 无运行时外部请求。

## 七、风险与回退

| 风险 | 概率 | 回退 |
|---|---|---|
| 前端迁移超时 | 中 | `alt/web-legacy/` 是旧版完整备份，可直接回滚 |
| E2E 在评审机器不可复现 | 低 | E2E 只作内部质量门，不要求评委运行 |
| 模型通道不可用 | 中 | 结果快照 `results/` 保证页面不空 |
| 真实评测受模型波动 | 高 | 记录后端真实模型名与温度，结果按模型归档 |
| 时间不够做完全部 P1 | 中 | 砍 P2 全部与 P1 第 13 条 |

## 八、明确不做
多用户/登录、云端部署、Docker、TTCN-3 代码生成、6G 规范支持（不存在）、虚拟 Key 网关（需 Postgres）、L2 计分。实时推送采用 **SSE 优先 + 轮询兜底**：`GET /api/job/<id>/stream` 断开或不可用时前端自动降级为 1s→3s 退避轮询。
