# 5 分钟演示脚本（简版；录屏以 `docs/DEMO-SCRIPT.md` 为准）

目标：让非专业评委在 5 分钟内看到「问题 → 演示 → 证据 → 局限 → 路线」。每步给出路由、动作与预期屏幕文字；不依赖现场模型时走快照路径。

## 演示前 30 秒检查
1. 双击 `start.bat`（同时起 Python :8000 与 Next :3000）；或分别运行 `py -3.12 scripts/serve.py` 与 `cd webapp && npm run dev`。浏览器打开 `http://127.0.0.1:3000/`。
2. 右上角状态为「proxy · 模型名」（绿色）；模型不可用时仍可用 `results/` 快照演示，跳过第 4 步的实时运行。
3. 若端口被占用，页面直接可用；不要重复启动。

## 0:00–0:30 一句话
> 把 3GPP 规范条款编译成可执行测试意图，再用确定性校验器自证对错；不是聊天机器人。

打开 `/about`，指「五分钟了解 → 问题/方案/效果/局限」。

## 0:30–1:30 评测页：先看硬指标
路由：`/eval`。
1. 四张统计卡：8 个用例、22 次 IE 生成调用、缺陷检出 31 / 31、官方答案误报 0 / 8。
2. 两张总览图：判定分布（7 通过 / 1 弃权）、缺陷按 R1/R2/R3 检出。
3. 点任一卡右上角 `?`，念出「计算式 + 分母 + 已知限制」。
4. 回 `/data` 指逐例矩阵：L1 8/8（含弃权例的结构解析）；L3 逐例给出，不报平均数；6.7.1.4 是弃权（灰色，不是失败）。

## 1:30–3:00 单例页：证据链
路由：`/case/6.7.1.3`。
1. 结论：通过；先显示“这条用例在验什么：网络把小区标记为禁止接入后终端是否重选”，再看结果解读。
2. 结果解读：这条用例在验什么 / 系统生成了什么 / 为什么是这个判定 / 数据怎么读 / 哪里还不确定。
3. 向下滚到「明细」：条款依据 → 六阶段 → 字段对照；点任一字段打开抽屉，展示「符号表路径 / 命中官方叶子字段 / 违规」。
4. 点「导出 Markdown」：文件可直接归档/评审；「导出 JSON」可接入用例库或 CI。
5. 切到数据页再回来、或刷新页面，结果与解读仍在（历史消息与实时结果同构）。

## 3:00–4:00 对话页：人在环上
路由：`/`。
1. 点示例问题「6.7.1.3 生成测试步骤」——精确命中，直接跑确定性阶段并生成。
2. 再输入具体场景（如「卫星小区被禁止接入」）——意图识别先调用一次轻量模型；命中后出现审批卡：候选消息就绪，点「批准并生成」才发起生成调用；点「取消」则不发起。
3. 指 `/case/6.7.1.4`：输入没有消息名 → 弃权，未生成 IE 字段内容，不计 0 分。

> 模型不可用时：跳过第 1–2 步的实时运行，改为展示既有结果与 HITL 文案；不要现场重试等待。

## 4:00–4:40 局限与诚实声明
打开 `/eval` 底部「已知限制」：
- 切片仅 8 个 NTN 用例；L3 分母 7（6.7.1.1 原文为 None）。
- 基线精确匹配全 0 是字段命名差异；页面默认用 relaxed 基线做公平对照。
- 结果解读覆盖 8/8；L2 不计分（16 条交换）；6G 未标准化，结论基于 Rel-19。
- 适用人群为设计假设，未做用户研究；人工耗时节省未验证，不作为承诺。
- 无专利/软著；真实性由可复现性担保：`bash scripts/verify_clean.sh`。

## 4:40–5:00 路线
1. 扩展第二个规范切片，验证跨条款泛化。
2. 把导出的 JSON/Markdown 接入 CI，做条款更新回归。
3. 与测试团队做小规模用户研究，量化节省时间与漏检率。

## 常见提问
- **和“把条款贴给 GPT”有什么区别？** 产物可被确定性校验器判错；不合格会拒收；每条结论有字段级证据。
- **为什么有些用例弃权？** 输入信息不足时不编造，也不计 0 分。
- **6G 还没冻结，凭什么算 6G？** 不宣称 6G 已实现。现在验的是 NR Rel-19；6G 冻结后迁移的是“规范 → 测试意图 → 确定性校验”的流水线，具体接 NTN 测试、AI 空口测试、网络自动化测试三个方向；AI 模型性能与射频指标不归本工具判。详见 `docs/6G-RELEVANCE.md`。
- **数字能重跑吗？** `bash scripts/repro.sh --live --force`（需模型与规范 PDF）；快照在 `results/`。
